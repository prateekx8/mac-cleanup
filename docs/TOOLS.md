# Tools: design

**Status:** the Tools section and Recover files R1 are built (`macguard_tools.py`, `macguard_recover.py`). The AI image and voice checks are next.

Mac Cleanup gets a **Tools** section: one-off utilities you open when you need them, next to the existing
cleanup, security and monitoring parts. Every tool runs on your Mac. You give it something (a memory card, a photo,
a voice clip), it looks at it locally, and it tells you what it found and how sure it is.

| Tool | What you give it | What you get | Design |
|---|---|---|---|
| **Recover files** | Nothing (it searches Trash, backups and snapshots), or a memory card / USB stick | Deleted files you can get back, and the files restored to a folder you pick | [RECOVERY.md](RECOVERY.md) |
| **AI image check** | A photo or picture (JPEG, PNG, HEIC, WebP) | Was it made or edited by AI? With the evidence, and how strong it is | [AI-DETECTION.md](AI-DETECTION.md) |
| **AI voice check** | An audio or voice clip (WAV, MP3, M4A, AAC) | Was the voice generated by AI? With the evidence, and how strong it is | [AI-DETECTION.md](AI-DETECTION.md) |

Build order: **Recover files (R1)**, then **AI image and voice check (phase A)**, then the deeper phases of each.

## How you use them

**App and web UI:** a new **Tools** panel shows one card per tool. Open a card, then:
- *Recover files*: search by name or type, or pick a card from the list of connected devices.
- *AI image / voice check*: drop a file on the card, or click **Choose file**. The result appears on the card:
  a verdict, the evidence behind it, and what the check can't tell you.

**CLI:**

```bash
macguard tools                      # list the tools and what each needs
macguard recover [--search NAME]    # light recovery: Trash, Time Machine, snapshots, git, editor history
macguard recover analyze disk4      # what's on this card, and the chances
macguard ai-check photo.jpg         # image or audio, picked from the file type
macguard ai-check voice.m4a --json
```

**MCP** (for Claude and other assistants): `tools_list`, `recover_search`, `recover_analyze`, `ai_check` (read-only).
Imaging a card and restoring files stay actions you confirm, like `apply_cleanup` today.

## Shared shape

Every tool returns the same kind of result, so the UI, CLI, MCP and reports show them the same way:

```json
{
  "tool": "ai-image",
  "file": "~/Desktop/photo.jpg",
  "verdict": "ai-proven | ai-declared | likely-ai | no-markers | unsupported",
  "headline": "Made with AI: signed Content Credentials say so",
  "confidence": "proven | strong | moderate | weak | none",
  "evidence": [{ "kind": "c2pa", "detail": "...", "weight": "proven" }],
  "limits": ["Metadata can be removed: no markers does not mean real"],
  "next": ["Open the original file, not a screenshot or a re-shared copy"]
}
```

Wording rules, for every tool:
- Say what was found and how strong it is. Never say "this is real" or "definitely human".
- Every result lists its limits.
- A "not found" result says what that does and doesn't mean.

## Files you give a tool

- **CLI:** the file is read where it is. Nothing is copied.
- **App and web UI:** the browser sends the file to Mac Cleanup's own local server (`127.0.0.1`, behind the same
  per-launch token as the rest of the UI). It's saved to `~/.macguard/tools/inbox/` readable only by you, analyzed, and
  deleted when the result is shown. The size limit is 200 MB per file.
- **Read-only:** tools never change the file you give them. Recovery never writes to the source card or disk.
- **Nothing leaves the Mac.** A tool may offer an online check (for example a provider's AI-speech classifier), but
  only as an extra button that says where the file would go, and only after you agree each time. It's off by default
  and never automatic.

## Code layout

Like `macguard_capture.py` and `macguard_devsec.py`, each tool is its own module, loaded only when used:

| Module | Contents |
|---|---|
| `macguard_tools.py` | The tool registry (`TOOLS`), the shared result shape, the upload inbox (save, size limit, cleanup) |
| `macguard_recover.py` | Recover files (tiers in RECOVERY.md) |
| `macguard_aicheck.py` | AI image and voice checks (phases in AI-DETECTION.md) |

New CLI subcommands go in `main()`, new UI routes under `/api/tools/*`, new MCP tools in `macguard_mcp.py`. The app
bundles every `macguard*.py` already (`build_app.sh`), so new modules ship without changes there.

## Optional helpers

Some checks get better with outside tools: `c2patool` for signed Content Credentials, `testdisk`, `ddrescue` and
`sleuthkit` for recovery, and local AI models for detection. Mac Cleanup:
- finds them with `shutil.which` and says which one it used in the result;
- works without them, saying what the extra tool would add;
- never installs anything by itself. `macguard doctor` lists each helper and its install command.

GPL tools are run as separate programs. Their code is never copied into this MIT project.

## Tests

- Each tool has a test file (`tests/test_recover.py`, `tests/test_aicheck.py`) with synthetic fixtures built in
  the test: FAT/exFAT images, PNG and JPEG files with hand-made metadata chunks, WAV files with INFO tags. Never real
  people's photos or voices, and never real disks.
- The upload route is tested for the token, the size limit, and that the file is deleted after analysis.
- `test_install.py` checks every tool's doc links and CLI names, like it does for the install guide.
